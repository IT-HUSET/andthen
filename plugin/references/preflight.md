# Preflight

The last act of authoring before a FIS or plan bundle goes to an unattended executor: put each point where that executor would guess to the user once, so the artifact ships with an answer or a recorded assumption, never the question. The calling skill names where each answer lands.

**Items** – what the run already surfaced: the author's collected ambiguities and undefined behaviors, self-review `Notes:` whose `blocks:` is not `no`, `Scope trades:`, and the caller's residue. No second detection pass – the self-review was the fresh reader. A mechanical defect – a broken anchor, a form-less proof, an unbound scenario, a missing tag – is fixed before hand-off, never asked.

**Sharpen, cite, then ask** – investigate first: a fork often closes on evidence in the code or the source, and a fork the `Decisions` document (see **Project Document Index**) or its Still Current notes settle closes by citation. A recommendation closes nothing: the user confirms it as the preselected answer. Ask what survives once, in one sitting, one item per question to answer, through the host's structured question tool where it fits: where the item bites and what it changes, the recommendation first as the preselected choice with its rationale, then the real alternatives with their observable consequence. Never offer a defer, skip, or later option, nor say what happens without an answer, which offers the same skip – the executor needs the answer, not the question. Check each answer against earlier ones sharing a surface, since two sound answers can contradict. A deeper skill is an offer, never a bounce, for a user who wants its record – an accepted one listed under `Decided:` with its command: an ADR (the `andthen:architecture` skill, `--mode trade-off`, recommended when the choice binds beyond this work or is costly to reverse), a spike (the `andthen:spike` skill), a PRD amendment (the `andthen:clarify` skill), matched by the Note's `blocks:` value. An accepted scope trade is a requirements answer; declined or unanswered, it writes nothing.

**Integrate once** – each answer into the prose that owns it, stated as the decision and replacing any `ASSUMPTION:` line it answers: no patch transcript, no decision-history section, no re-review. The body is what the executor implements, a second copy is what drifts, and a user's decision is not a reviewer's finding. A ratified recommendation ("your call", "take your recommendations") is an answer too; left as an `ASSUMPTION:` line, it tells the executor the point is still open. Every item under `AUTO_MODE`, with nobody to ask, and an item the user genuinely leaves unanswered – the session ends, the conversation moves on – takes the recommendation, its conservative reading, recorded per `automation-mode.md` § Recording an assumption: *"retry on failure" with no count → `ASSUMPTION: three retries – a rate limit or SLA on the called service would change it`.* That fallback is a safety net, never a choice put to the user; scope trades are never assumed.

**Ending** – `Decided:` and `Assumed:`, empty blocks omitted, then exactly one next command, all after the answers: the reply that asks ends on its last question, since a question placed after a finished report reads as already settled. No verdict line and no status of Preflight's own: every story it closes is `spec-ready`, since whatever an assumption leaves unclear is the executor's to settle by best reading, never a reason to stop. Size is never a decision – `OVERSIZE:` is advice the caller asks about.
