## Agent Workflows

- **Read-only fan-out subagents still edit source** – expect post-run changes only under `.agent_temp/`; save a recovery diff and confirm provenance (user WIP) before restoring.
- **A contract stated only in a step's reference never reaches a subagent that skips the step** – `plan --batch` skips Preflight, so the `ASSUMPTION:` form in `preflight.md` alone never reached the breakdown's story subagents; state a form where every writer loads it.
- **Claude Code's worktree isolation is unusable here; create worktrees yourself** – `isolation: "worktree"` is silently ignored for team agents, and for subagents it branches from the default branch (from the main checkout's HEAD in a linked worktree, which put a 2026-09-29 subagent on 0.x `main`), returns no path or branch, and its guard denies `git reset --hard` inside the worktree (docs and live eval, 2026-09-16/17). A plan run creates every story worktree itself from `BASE_BRANCH`; otherwise run subagents in this tree, one writer at a time. A manual `git worktree` + `cd` moves only Bash, because other tools resolve the session CWD; use `EnterWorktree`.
- **Claude Code's worktree isolation refuses file-tool edits outside the worktree but lets a shell command write there** (verified 2026-09-16, live eval) – so a story's writes, its `plan.json` row included, stay in its worktree and reach the main checkout with the merge.
- **A `git rm` enters the shared index and rides out on the next agent's commit** – in a shared worktree one session's staged deletion is already in the index when another commits, landing it in the wrong change. Commit by path (`git commit -- <paths>`), which leaves the rest of the index alone.
- **Per-story review depth compounds** – a four-line story drew four reviewer agents and most of an 18-minute run, all re-derived by the plan-level review; one fresh reviewer subagent invoking the `andthen:review` skill with `--quick` is the whole per-story review, and depth lives in that separate review.
- **An effort pin lives only in an installed agent definition** – an `Effort:` line in a spawn prompt does nothing on Claude Code and the Agent tool has no effort parameter; a role spawned as `subagent_type` with a role-first `name:` keeps its definition's pin (verified on 2.1.260). Read the tier back from `~/.claude/projects/<project>/<session>/subagents/*.meta.json` (`agentType` equals the role) and the `effort` field on the transcript's assistant turns before claiming it.
- **A slow eval cell is fan-out before it is wording** – `review` had regressed to seven subagents per run (per-lens critics, a guardrails pass, the filter); restoring `main`'s shape took the cell from 2363 s to 548 s. Count spawned subagents against `main` before trimming prose.
- **A Skill call tests the installed plugin, never the working tree** – to test edited skill text, copy `plugin/` to a scratch `SKILLROOT`, give a subagent the skill by absolute path, and run it in a detached throwaway worktree of the target project with git history forbidden. Replicate: three authoring runs of one story under identical text ranged 14–36 words per task outcome line (2026-09-19), wider than any rule-text effect measured, so an n=1 pair proves nothing.
- **A "blind" subagent still sees the installed skill listing** – a no-tools worker probed cold on *Prove-It Pattern* cited the `andthen:testing` description as its origin (2026-09-18), so a term the plugin's own descriptions name cannot be knowledge-probed in-harness; *Resolution Ladder*, named in no description, drew a clean "no".
- **A shared reference can name another file's sections as its own rubric** – `self-review.md:36` has the fresh reviewer apply `fis-authoring-guidelines.md`'s § Self-Check, § Plan-Spec Alignment Check and § Reverse Coverage Check by name, and nothing on the authoring side says so, so a cut that removes one of those headings silently breaks the instruction that justified the cut. Grep for the heading before deleting a section from a shared reference.
- **A Codex run that looks like it never asked may have asked into a void** – `request_user_input_async` returns `{"accepted":true}` immediately and never blocks; answers may never arrive, in DartClaw *and* in interactive Codex. Grep the rollout for `request_user_input` before blaming the prompt. Skills must route an ask only to a channel that holds the turn, else to the reply.
- **Every FIS has a `plan.json` beside it, one-story specs included** – so a `plan.json` on disk tells a run nothing: not a plan run from a story run, not one story from several, not a live plan from a pre-interview `intent.md` directory. The 2026-09-28 regression audit found this misreading behind three of its four P2s (`now-what` rows, `spec`'s one-story continuation) and in a pilot redirect; branch on what the argument names or on the plan's story count.
- **A measurement that failed becomes licence to reason, and the reasoning favours what you already shipped** – after a tool-call count failed and was recorded as *unmeasured*, the judge's silence (it grades the reply) was read as evidence, and both options not yet applied were scored down to near-zero. When a measurement fails, say which fact is missing and stop scoring.

## Cross-Agent Packaging

- **Never add `name: andthen-<x>` skill frontmatter** – Codex plugins register `<plugin>:<frontmatter-name>`, so it stutters as `andthen:andthen-x`.
- **Codex `$` sigil parsing rejects dots in loose-skill names** – hyphen prefixes only; a dot prefix once silently disabled explicit skill injection for every installed skill.
- **A dev plugin under another name mis-routes cross-skill calls** – the plugin name is the `andthen:` namespace, so a renamed copy's skills invoke the installed release's skills; dogfood the tree under the real name with the release disabled (`python3 scripts/andthen-plugins.py --path .`).

## Process & Tooling

- **`perl -0pi` interpolates `$(` and `$var` inside the replacement** – a rewritten shell line loses every variable silently and still parses; use a literal replacement (Python, `sed`) and grep the added lines for `$` before trusting the diff.
- **A substring test over `--help` text passes a retired verb** – `stale` is a substring of a surviving verb's help prose, so the cookbook audit let a document naming the retired verb through; test against the parser's choice list, not the rendered help.
- **A rule missing from a skill may be a ruled cut, not a regression** – rc.4's skill-review cut `review`'s follow-up narrowing by maintainer ruling (CHANGELOG rc.4, the glossary's Follow-up review row) but left `DECISIONS.md` § Review describing it, so a 2026-10-14 analysis called the cut a regression. Before calling a dropped rule a slip, check the CHANGELOG and glossary for a ruling; a cut that contradicts a `Decisions` note corrects the note in the same change.
- **A derived budget target predates the feature its row now carries** – `review (single lens)` was measured against a target derived before the quick path joined the skill, so the row reads over budget for content the audit verdicts KEEP; re-derive the target with the contract change, or record the gap as a decision.
- **Dogfood instance ≠ contract** – our own UL doc omits UL-08's `Bounded Context` column, so a spec calibrated on it missed conforming inputs. Check against the owning skill's template.
- **Dedup into a shared canonical can raise per-run cost** – moving a stanza into a reference loaded by more skills than the stanza had makes every path pay it; check load count before extracting.
- **A rewrite drops what reads as filler before it drops meaning** – a binding (a variable to its source, a flag to its consumer), a leading word that stops an ask, the sentence a run says to the user; losing two such phrases in the 2026-09-29 `spec` rewrite took a Codex criterion from 4/5 to 1/5. List each as a kept ledger row before the first edit, and have the fresh review check it. A move is a drop for every skill that no longer loads the target (`review`'s gap lens lost "upstream acceptance criteria are seeds" that way, 5/6 → 3/6).
- **A per-path word count taken from a read-set list passes while the body loads more** – S02's measurement took the `--batch` author's read-set from its FIS and passed at −0.1%, but the `spec` body linked `preflight.md` and `plan-schema.md` on the shared one-story line, so every story subagent loaded about 1,500 words more (+26%, caught by review). Derive each path's read-set from the links at its load site, conditions included.
- **A mode table's Read column is an unconditional load** – every invocation of that mode pays for the file however rarely its content applies; state the condition at a load site in the body, or split what only some runs need into its own reference.
- **A reshaped list directly above another list at the same indent merges with it** – the two render as one and items regroup under the wrong lead; read the rendered markdown after any prose-to-list reshape, or separate them with a paragraph.
- **A fold's load estimate must walk the host skill's unconditional steps** – folding `skill-review` into `review` as a lens was estimated at 7.1k words from body + lens files, but `review`'s `full-review.md` § Output always loads the report template and verdict reference (1,255), so the real path was 8.4k (+23%, 2026-09-25). Measure the whole invoked path of the host, not the files the fold adds.
- **A pruning rule's protected list is where bloat hides** – `SKILL-AUTHORING-GUIDELINES.md` once listed "enumerated inputs" among the markers that shielded a span from cuts, so pruning never reached `spec`'s input handling and it grew to 44% of the body against 2–9% in published skills. When a span survives every pruning pass, check whether a rule is shielding it before concluding it earns its place.
- **A cut's keeper only counts on every path that loaded the cut text** – three `security-review` cuts leaned on text only a dispatched `andthen:review` run loads, and the 2026-09-28 `exec-spec` pilot twice kept a rule for one path only (a fresh story but not a re-run; the story run but not the plan run's repair commit). Log each cut as `cut → keeper` with every run path (mode, flag, attended/unattended, fresh/re-run, dispatched) and check each loads the keeper.
- **A bare `bash` in `subprocess.run` is the WSL stub on Windows** – CreateProcess searches System32 before PATH, so the suite gets `C:\Windows\System32\bash.exe` (exit 1, no output) instead of Git Bash; resolve it with `shutil.which("bash")`, and normalise a Windows-style `$0` before `dirname` in scripts a native process launches.
- **Windows checkouts were CRLF until `.gitattributes` pinned LF** – `core.autocrlf=true` on runners and user machines; user artifacts still arrive with any EOL, so code that hashes bytes or `$`-anchors a raw `newline=""` read normalises `\r\n` first, and tests pass `encoding=` on every read – the default is cp1252 there.
- **A skill rename sweep is caught only where a name is a `/andthen:` sigil** – `audit-cookbook.py` scans four docs for sigils and nothing scans backticked names or descriptions, so the `prd` → `clarify` rename left retired names in the CHANGELOG, migration guide, install metadata, and frontmatter with every gate green. After a rename, `rg` the bare name across the repo and diff each skill's `Trigger on` clause against its predecessors; a `--validate-only` check that every description carries one would retire this bullet.
- **A skill fix proven on one host proves nothing for the other** – the old `visual-validation` failed in every Claude control, so only Codex, where builder framing flipped it to PASS, could show whether the edits mattered (2026-09-19). Reproduce a reported failure on the host that reported it before writing the fix, and keep an unedited snapshot as the control.
- **The repo hook refuses inline interpreters and recursive force deletes** – `python3 -c`, `sh -c`, `eval`, pipe-to-shell, and `rm -rf` (`hooks/configs/blocked-commands.json`); write a script file in the scratchpad and run it, and delete a tree with `find <dir> \( -type f -o -type l \) -print0 | xargs -0 rm` then `find <dir> -depth -type d -exec rmdir {} +` (`-type f` alone misses symlinks). The Bash tool caps one call at 10 min: launch a long run from a script with `nohup` and gate on real exit codes, not a `&&` chain over `grep`.
- **A retirement grep needs case and hyphen/space tolerance** – `execution-discipline.md` said "deeper-context pointers" lowercase with hyphens, and a `Deeper Context` grep missed it, the only consumer that could have left the executor skipping a Resolution Ladder rung. Use `rg -i 'deeper[- ]context'`, not a literal-case phrase.
- **`git grep` skips untracked files, so a FIS proof over a file the story creates misreads until the commit** – S04's `git grep -q` checks on its new `full-review.md` exited 1 on a correct tree (2026-09-26), and an `! git grep` absence check on such a file passes vacuously. Run those proofs with the file intent-to-add in a throwaway index (`GIT_INDEX_FILE=<tmp>`, `git add -N`), and re-run them after the commit.
- **`agent-browser screenshot --full-page` writes a file named `--full-page` into the repo root** – put the screenshot path before `--full`, and give it absolute paths, because its daemon's working directory is not yours. Prefer the host's built-in browser where it can render.
- **Shell commands must survive zsh, the Bash tool's shell on macOS** – zsh expands a word starting with `=` as a command path, so `echo =====` fails with `==== not found` and drops every `;`-chained command after it, and an unmatched glob such as `--include=*.py` aborts the call where bash passes it through (about 190 failed calls, 2026-10-05 to 10-20). Quote separators and globs whatever the shell: `echo '---'`, `--include='*.py'`.
