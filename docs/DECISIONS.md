## Still Current

### Workflow and skills

- **Where work starts: two questions, not one**: "do I know what to build?" and "one story or several?" are independent. `clarify` writes the PRD whatever the size; `spec` (one story) or `plan` (several) takes it, the one-story plan recording its path in `prd` – `null` only when there is none. An open design choice that binds beyond the work or is costly to reverse goes to `architecture --mode trade-off` first – `clarify`'s closing command when its PRD leaves one, Preflight's recommendation when authoring surfaces one. Amends ADR-015, under which a one-story PRD had to go through `plan`.
- **`clarify` writes the brief too, and has no `--auto`**: `--brief` stops the interview at `intent.md`, the intake shape the next run folds into the PRD, on any subject. ADR-015 barred `intent.md` because 0.x users picked between two skills by how complete the input looked; a flag on one skill is a stated choice. No `--auto`: the interview is the skill's value, and a pipeline that has requirements starts at `plan`. Reopens if an unattended pipeline needs a PRD `plan` cannot give it.
- **Specs are co-produced with the story breakdown**: `plan` authors the stories and their FIS together – specs decay when divorced from the story context that motivated them, and one cross-cutting review catches inter-story inconsistencies before execution.
- **No model-only or user-only skills**: a capability is a skill a user invokes by name and a subagent invokes with arguments. `user-invocable: false` is no home for procedures, and neither is a reference to "read X and perform it" – references are rubrics, few and one level deep. `disable-model-invocation` blocks Skill-tool invocation, and `now-what` routes to `exec-spec` and `exec-plan`. Reopens if a skill-invocable third tier ships.
- **Positioning terms**: "AI coding agents" in the tagline; "agentic engineering" only where disambiguation needs it; never "agentic software engineering".

### Authoring

- **The PRD carries its outcomes as body sections**: `Problem Definition > Target Users` and `Desired Outcome`, and `## Success Metrics` with baseline, target, and how observed. The Executive Summary derives from them, never the reverse, and validation rejects a metric that names a shipped capability. A FIS's Intent and Expected Outcomes cite these rows.
- **Preflight closes, never holds**: Preflight, the closing step of `spec` and `plan`, asks each open item once, recommendation first and preselected, with no defer option; under `--auto`, or for an item left unanswered, the recommendation is taken as an `ASSUMPTION:` where it bites. Authoring never writes `pending` or `blocked` – every story it closes is `spec-ready`, and what an assumption leaves unclear is the executor's to settle by best reading – so there is no `Closure:` verdict, hold, or reviewer re-entry per answer. The exec skills' pre-run checks are *admission*; the preflight name stays with the interview 0.x users know. Reopens on a run where an executed `--auto` assumption shipped behaviour the plan-level review did not catch.
- **The model judges which forks need the user**: skills and references say where asking happens and how a question is shaped, never which forks to ask – no per-case asking rules, no lists of forks that always need a question. On 2026-09-24 three rounds of such rules moved the `plan` eval to 1 of 5; a fixture with one fork that has no defensible default passed on the first two runs with no skill change, and the third failed only on a rubric that contradicted the skill. An eval that tests asking needs a fork like that, and its rubric requires that fork, never a question a capable model can default. Reopens on a run where a fork with no defensible default shipped as an assumption.
- **Scope trades are a self-review Note and a preflight question, not a skill**: the FIS self-review names, per component the floor option would not carry, the requirement clause buying it, the narrower reading that drops it, and what the Target User loses; Preflight puts those Notes to the user once per bundle, and an accepted trade amends the PRD through `clarify`. Never blocking – the design meets the requirements as written. The reviewer is the only agent holding both the design and the whole PRD, so a separate skill would only add surface. Reopens if trade Notes go unanswered in practice.
- **Document review is an authoring gate, not a `review` lens**: `clarify`, `spec`, and `plan` each run a fresh reviewer subagent on the `self-review.md` rubric, kept out of the author-loaded `fis-authoring-guidelines.md` so the author never reads the rubric it is judged by. There is no `--mode doc`: invoking `review` loaded roughly 9,000–12,000 instruction words to apply a few mechanical edits, and its matrix, report, and routing had no reader on those paths. Routing is a `blocks:` attribute on each Note, bundle coverage a per-FIS roster the `plan` gate checks; `review` keeps only lenses with an implementation target. Reopens if a hand-written PRD or FIS needs a standalone review that `clarify` amendment or `spec` re-entry cannot give, or a `plan` eval shows the roster missing a FIS-local defect.
- **Unstarted specs are re-authorable**: a story at `spec-ready` with no completed task is authoring-owned, so `spec` re-authors its FIS in place – every FIS belongs to a plan – and refuses once a task has completed or execution has begun. The author → review → amend loop needs no state-removal step before implementation exists.
- **A FIS carries only what the executor would miss**: the reason is signal and drift, not execution cost – reading a 6,000-word FIS is 2–5% of an `exec-spec` run, whose cost is turns × context. A fact restated from a cited source, a project document, or a scenario is a second copy that drifts; **Need-to-know** and by-reference `Verify` coverage are authoring rules, not a reviewer cut duty. Past ~6,000 words with the task count in range, `spec` compresses under **Single source of truth** before `OVERSIZE:` fires. Technical Overview lives in Architecture Decision as `Flow`, under its own ~10-line cap. Tried and dropped: a reviewer cut duty, a contradiction class in the self-review, lifting the Architecture Decision line cap (the section doubled). Reopens if an executor starts handing FIS excerpts to workers.
- **Over-engineered work is discarded, and the PRD is cut first**: the first evals harness (16k lines, never ran) was redone small rather than pruned – a PRD prescribing release-grade guarantees regenerates the same bloat. Before executing a PRD or plan, weigh its FR count and acceptance volume against the problem; prefer data-only extension points, one generic code path, and "running it is the test" over meta-tests.
- **Rejected concepts are Product non-goals, not a registry**: `clarify` and `backlog-triage` append a firmly rejected concept to the `Product` document's Non-Goals as one dated bullet and check that section before re-proposing one. Reopens if a project needs per-request provenance a bullet cannot carry.

### Execution

- **A decision never stops a run**: a decision is asked once, recommendation first, or under `--auto` taken as an `ASSUMPTION:` where it bites. Only an unusable call stops – input absent or invalid, missing credentials or tooling, a dirty tree the run does not own, an action without consent – and under `--auto` that stop is `BLOCKED: <what is needed>`, defined once in `automation-mode.md`; a run that tried and failed ends on its failure evidence. No `CONFUSION:`, `MISSING REQUIREMENT:`, `NO-OP:`, or per-skill trigger lists: nothing parsed them – DartClaw reads its own step-outcome envelope. The `blocked` story status has no writer; the schema enum keeps it so old bundles validate, read as `spec-ready`. Reopens if an orchestrator needs a stop reason beyond `BLOCKED:` versus failure.
- **`exec-spec` never stops on FIS detail**: the FIS is the executable brief, and authoring polices its detail. A broken anchor, a missing or form-less proof, an unbound scenario, or text a `sharedDecision` contradicts is filled with the best reading and recorded under Implementation Observations; only a contradiction with no defensible implementation stops a run. Orchestration stops – unresolvable provenance, unfinished dependencies, an unsafe action – stay. A foreign change overlapping the story's hunks is left uncommitted and reported: only the commit has to stay separate, never the work.
- **No edge-case knobs, no strictness blocks, one verification run**: the code root is the git root the skill runs in; a missing reviewer subagent falls back and says so in `Reviewed:` rather than blocking; a story runs one tier, not fast then full. A knob for a case the maintainer handles by hand costs a flag, a validity rule, a trigger, docs, and tests. Reopens on a case a frontier model running in the repo cannot handle without it.
- **`exec-plan` hands off the plan-level review**: its run gate is the full tier, iterated to green like any objective gate, and the report ends on a `Next:` line (`review --mode code,gap,security,outcome --fix`) instead of an in-session review loop – after N stories the run session is the most loaded context in the workflow, and `implement-fix` already owns review → fix → closure, including findings the per-story review left open. Reopens on evidence that a fresh-session review misses cross-story defects the run session caught.
- **A fresh-session hand-off says so in the line it prints**: `clarify`, `spec`, and `plan` close on `In a fresh session, run …`, and `exec-spec`, `exec-plan`, and a `review --fix` that owes a follow-up on `Next (fresh session): <command>`. The Architecture document's Conversation Boundaries map is for maintainers; the user sees only the printed line, and a bare command reads as "continue here". 0.x carried clean-session tips, 1.0 trims dropped them, and a 2026-09-24 manual `plan` run closed on a bare `exec-plan` command. The two words are the contract, not trimmable prose. Reopens if a host starts skill hand-offs in a fresh context on its own.
- **Per-story parallelism is plain git in the run session, not AndThen scripts**: `exec-plan --worktree` gives each story of a ready batch its own worktree – `git worktree add`, then a `--no-ff` merge per return – as prose the run session executes. Stories carry only code and FIS appends, and the run session writes `plan.json` after each merge, so nothing is reconciled; a merge conflict stops the line with the conflicting paths, worktree and branch preserved. No `--team`, `--max-parallel`, or `merge-resolve` squash protocol: Agent Teams is host-experimental, and squash was what made rollback, the `Squashed-story:` trailer, and `branch -D` necessary.
- **The `ops` skill and its script are retired**: `plan.json` has one writer – the run session executing the plan or spec, editing rows with its file tools per `plugin/references/plan.schema.json` – and story subagents report their state instead of writing it, which closes the 0.14.4 concurrent-writer collision (`e5202ed`) without reconciliation code. No validator for plans or models: none caught anything on a recorded run, a dangling FIS pointer surfaces when the FIS is opened, and producers check their candidate against the schema shipped beside its reference. Accepted: a malformed plan or model can be written. Reopens on a run where a hand-written row breaks execution or a consumer refuses a model.
- **Under `--auto`, remediation dispositions Notes on its own recommendation**: the reviewer's `Fix` bar is unchanged, but an unattended run has nobody to answer the list an interactive `implement-fix` returns, and 1.0 runs left `Note` and `NOTICED BUT NOT TOUCHING` items piling up unread. `implement-fix --auto` applies a Note it would change unasked – inside the reviewed surface, within Intent, one provable remedy, no open decision settled – defers the rest to the Tech Debt Backlog with the recommended remedy, or closes it with a reason; `review` reads a story's recorded open items as it reads earlier reports. Reopens if an eval shows it applying marginal observations.

### Review

- **Outcome validation is a `review` lens, not a skill**: `outcome` validates the finished feature against its PRD's Problem, Target Users, User Stories, and Success Metrics, walked as those users, and runs in `mixed` and the plan-level chain. Every mechanism it needs is `review`'s; it is not a gap dimension because gap's `## Verdict` block is frozen for comparability, and conformance and validation are different verdicts. Reopens if post-release measurement becomes an AndThen concern.
- **A PR is reviewed as a local tree, not through the API**: `review` takes `PR <n>` or a URL as the target. `git fetch refs/pull/<n>/head` plus a detached `git worktree add` with the hooks path and LFS smudge disabled executes nothing (verified on git 2.53), and the tree gives every lens its normal read and every tool a path. The safety boundary is execution, not fetch: the project's checks run when the head branch lives in the repository, since pushing there took write access; a fork PR (`isCrossRepository`) gets a static pass unless the user says otherwise. The worktree follows the host (`.claude/worktrees/` on Claude Code), else the session temp directory; a `CLAUDE.md` in it can reach Claude Code's context, accepted under the evidence-not-instructions rule.
- **A review reads earlier reports as input, never scope**: it states each earlier finding resolved, still open, or regressed and names the latest in `**Follows**:`. Scope narrows only when the request asks for a re-review or follow-up after fixes, which stays a full run with its own report and verdict. Reopens on evidence that un-asked full re-reviews drive cost.

### Project documents

- **Durable documents carry no size ceilings**: Index entries are name and location, then the read/update trigger – no size number, since nothing enforces one. Documents are read whole and so stay short; one that outgrows that becomes an index over topic files beside it, one pointer line each, a shard opened when the task names its topic – by hand, with no verb or size check. The numbers that are load-bearing live where they are used: the FIS oversize threshold in `spec` and the authoring guidelines, the 200-character glossary row rule in the Ubiquitous Language header.
- **The shipped Index template carries no Product Backlog or Changelog entry**: no skill reads a backlog – a deferral stays in its PRD's `Scope > Out of Scope`, a put-off fix in Tech Debt – and a changelog would need a completion clause in `exec-spec` and `implement-fix`, not an Index entry. A project that keeps either adds its own entry.
- **No `Stack` document**: every row of its template projected the manifest, the lockfile, an ADR, or the Architecture document's Integration Points, and adopting projects showed versions drifting from the lockfile within weeks. The baseline (language, runtime, main framework) is one sentence in the Architecture document's System Overview, a library choice with a reason is a Decisions row, a rejected one a Product non-goal, and versions stay in the manifest. Reopens if a polyglot repository with no single manifest needs an inventory the Architecture document cannot carry.
- **No `close-plan` verb**: the rule is one sentence in the Architecture document's artifact-lifecycle paragraph – bundle deleted before merge, Implementation Observations read first; `plan.json` already shows the statuses. Reopens if an unattended pipeline needs a machine-checked close-out.
- **Tracker setup is first-use, not an `init` gate**: `init` always writes the Index entry and offers the file only as an optional document; the first skill that needs the backend – a reader handed a non-GitHub URL, `backlog-triage` with no remote, `tracker` at first publish – offers to create it, and `--auto` blocks naming the `Backend:` line to set. `Backend: none` reads as absent. Accepted: a non-GitHub project's first `--auto` run blocks until the document exists. Reopens if a project needs the backend declared before any skill sees a URL.
- **`init` wires the rules and role agents in prose, not a script**: `wire.py` was 328 lines plus 388 test lines for work the prose does in 18, re-deriving what the agent already has in context. Reopens if an unattended `init` needs a machine-checkable wiring result.
- **The atlas schema is for code-structure graphs only**: `ref` anchors to repo-relative paths and `evidence` makes every edge refutable against code, so a non-code graph (a workflow, a status board) follows the projection pattern – typed JSON, invariant core, its own schema – but never adds a third `kind`.

### Packaging and measurement

- **No tests inside the plugin directory**: every suite lives in `tests/`, because both hosts install `plugin/` wholesale with no exclude list – a test beside a shipped script ships to every user. Reopens only if a host gains an install-time exclude.
- **Codex does not substitute `${CLAUDE_PLUGIN_ROOT}` or `${CLAUDE_SKILL_DIR}` in skill text**: its shim is a hook environment variable only. References are therefore skill-root-relative, since both hosts announce that root: `../../references/<name>.md` for a canonical, `<skill-dir>/scripts/<name>` for a bundled script, no tokens anywhere (`--validate-only` rejects them). Reopens if the Agent Skills spec standardizes a path variable; upstream `openai/codex#35702` asks for Claude-compatible aliases.
- **Leanness is measured per consuming path, and dedup never creates a reference file**: the number is the active lines a use case loads – body plus every reference it names – not SKILL.md size; a pointer pulls the whole file into every consuming bundle, so one 40-word sentence copied into five skills costs less than five links to an 850-word canonical. Report per-path loaded lines before and after; minor duplication with canonical wording is the accepted shape.
- **No context-budget gate**: shipped-prompt size is bounded by `install-skills.sh --validate-only` and the shipped-surface word budget; the ratchet cost a fixtures directory, a ceilings file, and wording gotchas without producing a finding after its baseline.

### Evals

- **Eval cells run in the operator's own environment**: real `HOME` and `~/.claude` with its rules, role agents, and MCP servers; the working tree is the registered marketplace source. Isolation made cells unrepresentative (subjects saw no `reviewer` role, so critics ran as general-purpose at high effort). Codex keeps only what DartClaw's pinned state dir forces. A case with a fuzzy criterion is fixed or cut, never kept.
- **`claude plugin eval` is not the eval harness**: Claude-only, no code graders, long journeys cannot run in it, and a skill-trigger suite is rejected outright. Wanted instead: baseline cells inside the DartClaw harness measuring core journeys against no plugin. Reopens if plugin eval gains code graders or a second host.
