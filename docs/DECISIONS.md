## Still Current

<!-- Load-bearing decisions that don't warrant a full ADR. One bullet each.
     Format: **<Topic>**: <decision + brief rationale>. -->

- **`disable-model-invocation` on skills**: rejected without skill-specific exceptions – it blocks Skill-tool invocation. Reconsidered for `exec-spec` and `exec-plan`, but both remain callable by `now-what`, so their current model-invokable policy stays. Reopens if a skill-invocable third tier ships.
- **No tests inside the plugin directory**: every suite lives in `tests/`, because both hosts install `plugin/` wholesale with no exclude list – a test beside a shipped script ships to every user, and these suites read repo fixtures the install does not carry anyway. Reopens only if a host gains an install-time exclude.
- **Unstarted specs are re-authorable**: a story at `blocked` or `spec-ready` with no completed task is authoring-owned state, so `spec` re-authors the FIS in place – every FIS is a plan story (ADR-013, ADR-015) – and refuses only once a task has completed or execution has begun. Chosen over a retirement verb: the author → review → amend loop should not need a state-removal step before implementation exists.
- **`exec-plan` hands off the plan-level review**: the run gate is the full tier with one repair round, and the report ends on a `Next:` line (`review --mode code,gap,security,outcome --fix`, one paste that runs `implement-fix` on the report) instead of an in-session review loop – after N stories the run session is the most loaded context in the workflow, and `implement-fix` already owns review → fix → closure, which under ADR-014 is also where findings the per-story review left open are enforced. Reopens on evidence that a fresh-session review misses cross-story defects the run session caught.
- **Outcome validation is a `review` lens, not a skill**: `outcome` validates the finished feature against its PRD's Problem, Target Users, User Stories, and Success Metrics, walked as those users, and runs in `mixed` and the plan-level chain. A lens because every mechanism it needs is `review`'s – PRD discovery from `plan.json`, Intent Context, the Coverage Matrix, the finding contract, the `clarify` and `implement-fix` routing; not a gap dimension because gap's `## Verdict` block is frozen for comparability, and conformance and validation are different verdicts. Reopens if post-release measurement ever becomes an AndThen concern.
- **No `close-plan` verb**: it was a `done/skipped` check plus deletion of a pinned file set, at 60 script lines, 362 test lines, and a row in every verb list; `progress` already shows the statuses and the set is two kinds of file. The rule survives as one sentence in the Architecture document's artifact-lifecycle paragraph – bundle deleted before merge, Implementation Observations read first. Reopens if an unattended pipeline ever needs a machine-checked close-out.
- **`init` wires the rules and role agents in prose, not a script**: `wire.py` was 328 lines plus 388 test lines for work the prose does in 18, and a script editing a bounded rule section in someone's instruction file re-derives what the agent already has in context. Reopens if an unattended `init` ever needs a machine-checkable wiring result.
- **The shipped Project Document Index template carries no Product Backlog or Changelog entry**: no skill reads a backlog, a deferral stays in its PRD's `Scope > Out of Scope` and a put-off fix has the Tech Debt entry, and a changelog needs a completion clause in `exec-spec` and `implement-fix` rather than an Index entry. A project that keeps either document adds its own entry.
- **The context-budget gate is retired (2026-09-11)**: `measure-context-budget.py`, its ceilings file, its fixtures, and its CI step are gone. It was a phase-1 baseline tool promoted to a ratchet; shipped-prompt size is already bounded by `install-skills.sh --validate-only`, and the ratchet cost a fixtures directory, a ceilings file, and wording gotchas without producing a finding after the baseline.
- **Project Document Index ceilings are retired (2026-09-12)**: entries drop the per-document size number and take a two-line shape – name and location, then the read/update trigger. Every enforcement of the number had already gone (ADR-008 → ADR-012 → ADR-013, and the context-budget gate on 2026-09-11), so nothing read it; the intent survives as one preamble sentence, that documents are read whole and so stay short. The two numbers that were load-bearing live where they are used: the FIS oversize threshold in the `spec` skill and the authoring guidelines, the 200-character glossary row rule in the Ubiquitous Language header. Reopens if a durable document bloats past what a run should pay for reading it.
- **Shards return as a convention (2026-09-15)**: rc.1 folded `learnings/` topic files into one document when it cut the ceiling and graduation machinery, and the shape went with the mechanism. It is back as prose only – an indexed document may be an index over topic files beside it, one pointer line each, a shard opened when the task names its topic – with no ceiling, verb, or size check; the reopen condition above is answered by sharding by hand, not by a number.
- **Rejected concepts are Product non-goals, not a registry (2026-09-12)**: the Out of Scope Registry sat between the `Product` document's Non-Goals and a PRD's `Scope > Out of Scope`, and no adopting project – this one included – ever created it. `clarify` and `backlog-triage` append a firmly rejected concept to Non-Goals as one dated bullet and check that section before re-proposing one. Reopens if a project needs per-request provenance a bullet cannot carry.
- **The `Stack` document is retired (2026-09-12)**: its template had no judgment section – every row was a projection of the manifest, the lockfile, an ADR, or the Architecture document's Integration Points – and the two adopting projects that kept one showed the cost: pinned versions drifted from the lockfile within weeks, an ADR deferred a fact to it that never landed, and nothing read it mid-task. The as-built baseline (language, runtime, main framework) is one sentence in the Architecture document's System Overview, infrastructure and external services are its Integration Points, a library choice with a reason is a Decisions row and a rejected one a Product non-goal, and versions stay in the manifest. Reopens if a polyglot repository with no single manifest needs an inventory the Architecture document cannot carry.
- **`clarify` writes the brief too, and has no `--auto` (2026-09-15)**: amends ADR-015 on two points. `--brief` stops the interview at `intent.md` – the intake shape the next run already folds into the PRD – on any subject, a feature or a decision; only the landing and the project anchors are feature-shaped, so the PRD path is unchanged. ADR-015 barred `intent.md` as an output because 0.x users chose between two skills by how complete the input looked; a flag on one skill is a stated choice, not an inference. `--auto` retires: the interview is the skill's value, and a pipeline that has requirements starts at `plan`. The interview runs in rounds over the settled frontier and plays the settled picture back for a yes before writing. Reopens if an unattended pipeline needs a PRD `plan` cannot give it.
- **The PRD carries its outcomes as body sections (2026-09-15)**: `Problem Definition > Target Users` and `Desired Outcome`, and `## Success Metrics` with baseline, target, and how observed. The Executive Summary derives from them – before, users and metrics lived only there, breaking the template's own summary-not-source contract exactly where value sat – and validation rejects a metric that names a shipped capability. A FIS's Intent and Expected Outcomes cite these rows.
- **`Closure:` has two values, `READY` and `BLOCKED` (2026-09-14)**: rc.1's `DEFERRED` was operationally identical to `BLOCKED` – both set the story `blocked` and both prescribed the same re-run – and its name matched the PRD's own deferrals, which a real `plan` run then reported as the verdict over a bundle of nine `spec-ready` stories. The verdict restates the story status the run just wrote, and `BLOCKED` is followed by each held decision and what settles it, so the line never stands alone. Reopens only if a consumer needs to distinguish a deferral from an open decision without reading the FIS.
- **Scope trades are a self-review Note and a preflight question, not a skill (2026-09-15)**: the FIS self-review names, per component the floor option would not carry, the requirement clause buying it, the narrower reading that drops it, and what the Target User loses; preflight puts those Notes to the user beside the blocking decisions, once per bundle, and an accepted trade amends the PRD through `clarify`. The reviewer is the only agent holding both the design and the whole PRD – a batch `spec` subagent reads its story's spans – and a skill would be that review chained to the amendment, at the cost of a README row, an eval case, and a cookbook recipe. Never blocking: the design meets the requirements as written. Reopens if trade Notes go unanswered in practice.
- **Preflight is the closing step's name; the exec skills' pre-run checks are admission (2026-09-15)**: rc.1 renamed the 0.x `preflight` skill's interview to Decision Closure while `exec-spec` took the word for its validity checks, inverting the lineage users knew. The step is Preflight again in `spec` and `plan`, the verdict stays `Closure: READY | BLOCKED`, and `exec-spec` / `exec-plan` say admission. Reopens only with a user-facing reason to rename again.
- **Document review is an authoring gate, not a `review` lens (2026-09-15)**: `--mode doc` retires. Its only shipped consumers were the fresh-context self-reviews in `clarify`, `spec`, and `plan`, each reading back applied fixes and residual Notes only while loading the whole review read-set – roughly 9,000 to 12,000 instruction words, plus the `implement-fix` hop under `--fix` – to apply a few mechanical edits; the coverage matrix, Guardrails line, report file, readiness label, and Downstream Routing had no reader on those paths. The three keep their fresh reviewer subagent, which now loads a rubric instead of invoking `review`: `self-review.md`, one shared contract with a PRD and a FIS section, kept out of the author-loaded `fis-authoring-guidelines.md` so the author never reads the rubric it is judged by. Routing survives as a `blocks:` attribute on each Note, scope trades as the self-review's `Scope trades:` block, bundle coverage as a per-FIS roster the `plan` gate checks. `review` keeps the lenses with an implementation target – `code`, `gap`, `security`, `outcome`; a requirements document is reviewed where it is written and again as a baseline. Reopens if a hand-written PRD or FIS needs a standalone review that `clarify` amendment or `spec` re-entry cannot give, or a live eval run of the `plan` case shows the roster missing a FIS-local defect the lens caught.
- **Codex does not substitute `${CLAUDE_PLUGIN_ROOT}` or `${CLAUDE_SKILL_DIR}` in skill text (2026-09-16)**: its shim is a hook environment variable only, and every Codex eval rollout shows the model searching the plugin cache for the file, once missing. No shipped text explains the tokens: a per-skill note is 21 copies of one fact, and an instruction-file line is a pattern no other dual-host plugin uses and leaks packaging into users' projects. The reference form is therefore skill-root-relative, since both hosts announce that root: `../../references/<name>.md` for a canonical, `<skill-dir>/scripts/<name>` for a bundled script, no tokens anywhere (`--validate-only` rejects them). Reopens if the Agent Skills spec standardizes a path variable; upstream `openai/codex#35702` asks for Claude-compatible aliases and is unanswered.
- **Per-story parallelism is plain git in the run session, not AndThen scripts (2026-09-16, amended 2026-09-21)**: rc.1's team-mode retirement (`db62b5b`) also dropped `exec-plan --worktree`, which `main` had; that removal was unsanctioned and is reversed. The mode is one worktree per story of a ready batch, `git worktree add` and a `--no-ff` merge per return, written as prose the run session executes. Since 2026-09-21 the stories carry only code and their FIS appends – `plan.json` has one writer, the run session, which writes the row after the merge – so nothing is reconciled and the old guards reduce to one: a merge conflict stops the line with the conflicting paths, worktree and branch preserved. Not restored: `--team`, `--max-parallel`, the `merge-resolve` skill and its squash protocol – Agent Teams is host-experimental, and squash was what made rollback, the `Squashed-story:` trailer, and `branch -D` necessary.
- **A PR is reviewed as a local tree, not through the API (2026-09-15)**: `--from-pr`, `--worktree`, and `from-pr-mode.md` retire; `review` takes `PR <n>` or a URL as the target. The API-only mode existed so no PR-controlled code could run, and feared checkout itself: a plain checkout does run PR hooks when `core.hooksPath` points into the tree, but `git fetch refs/pull/<n>/head` plus a detached `git worktree add` with the hooks path and LFS smudge disabled executes nothing (verified on git 2.53). The tree gives every lens its normal read and every tool a path, `outcome` included, and replaces blob reads, the OID retry loop, four rejection rules, and a duplicate fetch protocol in the since-retired `explain-changes` skill. The safety boundary is execution, not fetch: the project's checks run when the head branch lives in the repository, since pushing there took write access; a fork PR (`isCrossRepository`) gets a static pass unless the user says otherwise. The worktree follows the host (`.claude/worktrees/` on Claude Code), else the session temp directory; a `CLAUDE.md` in that tree can reach Claude Code's context, accepted under the evidence-not-instructions rule. Note: `docs/temp/research/from-pr-simplification-2026-09-15.md` (local).
- **No edge-case knobs, no strictness blocks, one verification run (2026-09-13)**: `--code-dir`, `CODE_DIR`, and `ops commit --root` retired (`17544a4`) – the code root is the git root the skill runs in, and multi-repo setups work by hand without a flag; no skill ends in `BLOCKED:` on a missing reviewer subagent or similar strictness – it falls back and says so in `Reviewed:`; a story runs one tier, not fast then full. A knob for a case the maintainer handles by hand costs a flag, a validity rule, a trigger, docs, and tests, and complexity carried over from `main` is not grandfathered. Reopens on a case a frontier model running in the repo cannot handle without it.
- **Over-engineered work is discarded, and the PRD is cut first (2026-09-02)**: the first evals harness (16k lines, never ran) was archived and redone small rather than pruned – a PRD prescribing release-grade guarantees regenerates the same bloat on re-execution. Before executing a PRD or plan, weigh its FR count and acceptance volume against the problem; prefer data-only extension points, one generic code path, and "running it is the test" over meta-tests.
- **Leanness is measured per consuming path, and dedup never creates a reference file (2026-09-14)**: the number is the active lines a use case loads – body plus every reference it names – not SKILL.md size; a pointer pulls the whole file into every consuming bundle, so one 40-word sentence copied into five skills costs less than five links to an 850-word canonical. Report per-path loaded lines before and after; minor duplication with canonical wording is the accepted shape.
- **No model-only skills (2026-09-13, absolute since 2026-09-21)**: `user-invocable: false` is not a home for procedures – a capability is a skill a user can invoke by name and a subagent invokes with arguments. A procedure shipped as a reference ("read X and perform it") is the same anti-pattern: references are rubrics, few and one level deep.
- **Eval cells run in the operator's own environment (2026-09-15)**: real `HOME` and `~/.claude` with its rules, role agents, and MCP servers – no redirected config dir, empty home, env allow-list, or candidate registration; the working tree is the registered marketplace source. Isolation was machinery that also made cells unrepresentative (subjects saw no `reviewer` role, so critics ran as general-purpose at high effort). Codex keeps only what DartClaw's pinned state dir forces. A case with a fuzzy criterion is fixed or cut, never kept – no flakiness, no over-engineered tests.
- **`claude plugin eval` is not the eval harness (2026-09-13)**: Claude-only, no code graders, long journeys cannot run in it, and its scored judge is the model `evals/run.py` was designed against; a skill-trigger suite is rejected outright. Wanted instead: baseline cells inside the DartClaw harness – a `<case>-baseline/` plain-prompt workflow, a shared outcome-only rubric, one knob that skips plugin registration – measuring core journeys against no plugin. Reopens if plugin eval gains code graders or a second host.
- **The atlas schema is for code-structure graphs only (2026-08-16)**: `ref` anchors to repo-relative paths and `evidence` makes every edge refutable against code, so a non-code graph (a workflow or effort map, a status board) follows the projection pattern – typed JSON, invariant core, validator, deterministic renderer – but never adds a third `kind`; the 3D form suits graphs, not boards.
- **The review campaign is removed (2026-09-18)**: a review reads earlier reports on its target as input, never scope – it states each earlier finding resolved, still open, or regressed and names the latest in `**Follows**:` – and scope narrows only when the request asks for a re-review or follow-up after fixes, which stays a full run with its own report and verdict. The campaign (`694cca1`) narrowed a review unasked and had no recorded rationale. Reopens on evidence that un-asked full re-reviews drive cost.
- **FIS length is not optimised for execution cost (2026-09-20)**: reading a 6,000-word FIS is 2–5% of an `exec-spec` run, whose cost is turns × context – tool output spills, screenshots, and repeated suite runs fill it, not the spec. The 1.0 rule text already authors at 96–122 words per scope unit against 156 for 0.40; the long specs measured came from a launch prompt asking for evidence inline and from closure, not from the rules. Length still costs at authoring time, which the word limit bounds: past ~6,000 words with the task count in range, `spec` compresses under **Single source of truth** before `OVERSIZE:` fires, since every skill-caused discarded authoring run measured was a word-limit split. Tried and dropped: a reviewer cut duty, a contradiction class in the FIS self-review, lifting the Architecture Decision line cap (the section doubled). Reopens if an executor starts handing FIS excerpts to workers, so that length enters more than one context.
- **Positioning terms (2026-09-01)**: "AI coding agents" in the tagline; "agentic engineering" only where disambiguation needs it; never "agentic software engineering".
- **`ops validate-model` retired (2026-09-20)**: a pre-write gate every producer ran on its own output – the verb, its tests and the prose sites go; producers, models, the schemas – shipped beside the model references, read at authoring – and `plan`'s model-reading path stay. Accepted: a malformed model can land in `docs/models/` unchallenged. Reopens if a downstream consumer refuses one.
- **The `ops` skill and its script are retired (2026-09-21)**: `plan.json` gets one writer – the run session executing the plan or spec, editing rows with its file tools per `plan.schema.json` – and story subagents report their state instead of writing it, which closes the 0.14.4 concurrent-writer collision (`e5202ed`) without reconciliation code. `validate-plan` goes with it on the Decision Rule: no recorded run where it caught anything, a dangling FIS pointer surfaces when the story's FIS is opened, and a cycle leaves stories never-ready and unstarted in the closing report. The schema moves to `plugin/references/plan.schema.json` as a shared canonical, checked by the skill that writes a plan the way the model references already are. Accepted: a malformed plan can be written. Reopens on a run where a hand-written row breaks execution.
- **Specs are co-produced with the story breakdown (2026-09-21)**: the `plan` skill authors the stories and their FIS together, because specs decay when divorced from the story context that motivated them, and batching lets one cross-cutting review catch inter-story inconsistencies before execution.
