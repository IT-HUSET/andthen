# Learnings: Eval harness (DartClaw)

<!-- Shard of docs/LEARNINGS.md; same admission and pruning rules. Read when running, debugging, or reading results of the live evals. -->

- **A `format: path` output resolves from uncommitted worktree changes** – an executor commits its story before returning, so the resolver finds nothing left; execution workflows return completion as `format: text`.
- **The stall watchdog (5 min, cancel) kills a headless turn waiting on a subagent** – set `governance.turn_limits.stall_action: warn`. DartClaw before `71b1e3fa` (feat/0.25.2) also restarted the process at turn end and killed background children (`review`: four passes "stopped, not completed"); a per-site `run_in_background: false` rule worked around it and was retired once the harness held the turn – a host's spawn default is host syntax, not a skill contract.
- **The structured-output extraction turn allows two turns and no tools** – a schema field the model must compute (git tree hashes, changed paths) fails the step; ask only for what the run already said.
- **Under `--setting-sources project`, register an eval candidate with `--plugin-dir` in a wrapper executable** – user-scope plugin enablement is invisible there (DartClaw 0.25.1 forced the flag and subjects reported the skill missing). `--settings` does register a plugin, but DartClaw 0.26.2's skill preflight probes without the provider's `settings` and refuses the run ("Missing skills"); the executable is all the preflight and the steps share (Claude Code 2.1.282, 2026-09-25).
- **`Permission mode forced to default – CLAUDE_CODE_SUBPROCESS_ENV_SCRUB is set` in a cell's stderr is benign** (2026-09-21) – DartClaw sets that variable on every Claude spawn; a cell logging it ran to completion. Read the workflow's `errorMessage` in `stdout.jsonl` for the real cause.
- **A Claude subject loads every `CLAUDE.md` above its working directory** – its own Git root does not stop the walk, so a workspace under this repo handed it the repo's `CLAUDE.md` and `CLAUDE.local.md`; a cell runs under `$TMPDIR` for that reason.
- **A Claude eval cell needs no environment redirection, a Codex cell does** – DartClaw passes the parent environment to the Claude child untouched, which is where its login resolves; Codex's `CODEX_HOME` is pinned to `<data_dir>/credentials/codex` under subscription auth whatever the environment holds, so the candidate must be registered there. Either way `login_store_guard` refuses the operator's real login directories, so subscription credentials are copied into `<data_dir>/credentials`.
- **A parsed-shape change breaks eval cases keyed on the old shape** – rc.3's report template (`Finding N`) left the `implement-fix` oracle matching `F1` and both cases' input reports in the old format, failing both hosts; `rg` `evals/cases/` for the old token in the same change.
- **A judged criterion about what a run dispatched fails unless the case declares an output carrying it** – the judge quotes only declared outputs and the retained workspace, never the subject's tool calls, so `spec-two-stories` failed its per-story-author and bundle-review criteria on both hosts while the Claude transcript showed exactly those subagents (2026-09-25). Declare the evidence as a schema'd output, as `spec`'s `review_evidence` and now `dispatch_evidence` do.
- **A DartClaw bash step's `{{var}}` substitution must be an unquoted argument** – quoting it fails at run time with "command substitution failed" while `dartclaw-workflow validate` passes it.
- **A DartClaw upgrade can move the retained records out from under the readers silently** – 0.27.1 moved session messages and `kv.json` into `data/standalone/`, the readers fell back to empty, and every judge of a full tier graded an empty transcript (2026-10-02). After an upgrade, check one cell's `judge-request.json` carries subject messages before trusting a verdict.
- **An aggregate over `.agent_temp/evals/` mixes eras and retired cases** – retention keeps the newest three per case and provider whatever their age, and the tree keeps directories for cases that no longer exist, so a sweep of every `result.json` showed `canary` 3 ERROR on both hosts (2026-09-02, "unresolved on PATH") beside current cells and read as a broken suite. Filter to cases under `evals/cases/` and read the newest per provider with its date.
- **A cell's `candidate:` hash does not identify the surface it measured** – every cell run against a dirty tree reports the same SHA plus `(dirty)`, so seven `plan` cells at `ce1e845 (dirty)` spanned two different plugin surfaces. Each cell keeps the whole plugin it ran under at `candidate/plugin/`; grep that copy for the clause in question to group cells.
- **An eval subject reads its prompt from `subject-workflow.yaml`; `prompt.md` is the judge's input only** (`evals/step.py:58`) – a fix made only in `prompt.md` never reaches the subject, so three passes once read as proof of a fix that never shipped (2026-09-28). Edit both, or check the workflow's `prompt:`. No judge-only entry point exists, so a rubric change needs a re-run.
- **Attribute eval cells by the report's `run` column, never by a directory diff** – launchers sharing a tree each claimed the other's landed cells (6 and 12 on 2026-09-29). Concurrent tiers also sweep the same staging cells, so `stage.sweep` treats a move the other got to first as done.
- **A headless cell that ends "waiting on S0x" is a DartClaw 0.26.2 race, not a skill regression** (diagnosed 2026-09-29; 2 of 30 `plan` cells stalled after `breakdown.md` Step 4's await clause) – when the last subagent finishes during an earlier one's notification turn, `background_tasks_changed` is already empty, so DartClaw completes the step there and its finalizer restarts the process, killing the queued task-notification. The `stderr.log` signature is `Background tasks: 0 listed, 0 awaited`, `Terminal result ... after 1 held result(s)`, then the restart; do not reword skills for it – the fix is in DartClaw's `ClaudeCodeHarness`, which must also hold while a finished task's notification is still owed.
